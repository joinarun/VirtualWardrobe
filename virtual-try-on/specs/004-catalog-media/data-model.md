# Catalog and media data

Category:id,parent_id,name≤120; cycle-free tree. Brand:id,store_id nullable,name≤120,logo_media_id nullable; unique case-insensitive name within global/store scope. Product:id,store_id,sku≤80 uppercased and unique per store,title≤180,description≤8000,category_id/brand_id nullable for drafts,labelsJSON string array max20×50chars,price numeric12,2≥0,fabric/colour/size≤120,status,availability,try_on_enabled,cover_media_id/reference_media_id,created/updated timestamps,dataset_id.

MediaUpload:id,owner_account_id,store_id/product_id/brand_id target references,purpose PRODUCT_IMAGE/PRODUCT_VIDEO/STORE_LOGO/BRAND_LOGO,declared_mime/bytes,token_hash,state AUTHORIZED/UPLOADING/UPLOADED/PROCESSING/VALIDATED/REJECTED/DELETED,object_key/thumbnail_key,normalized_mime,width,height,duration_seconds,position,expires_at,created_at,dataset_id. Pending states reserve a product slot; successful finalization changes to VALIDATED. The media ID is the upload ID, avoiding duplicate records for retries. A target logo points to a validated upload; old logos are marked deleted after replacement.

All object keys are generated by the server under quarantine/UUID or catalog/store/UUID. No user filename is used as a path. GCP adapter supports private/saved/temp prefixes for later private-photo modules but no customer image routes exist in this feature.
